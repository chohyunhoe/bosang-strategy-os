# 보상전략 OS v0.1 화면설계서

## 1. 설계 원칙

화면은 `stable16`의 앱셸과 기존 `data-section` 구조를 보존한다. v0.1 종료를 위해 새 프레임워크나 전면 UI 재설계를 하지 않는다.

화면 우선순위는 다음과 같다.

1. 현재 사건과 추출 상태를 즉시 확인
2. 편입토지·표준지·사례·평가수치를 빠르게 비교
3. 검토가 필요한 항목과 확정되지 않은 항목을 명확히 구분
4. 지도·수치·쟁점·주장문이 하나의 실무 흐름으로 이어짐
5. 모바일에서는 핵심 카드와 검토 상태를 먼저 보여주고 대형 표는 보조로 둠

## 2. 전체 내비게이션

### Workflow 1 — 관제 및 원본

목적: 현재 입력 사건과 추출 상태 확인

핵심 요소:
- 평가서 업로드
- 파일/추출 상태
- Parser 실행 상태
- OCR 검수 진입
- 사건 초기화/교체

완료기준:
- 이전 사건 데이터 혼입 없음
- 업로드 1건과 Parser 결과 연결 명확

### Workflow 2 — 토지 및 공적자료

목적: 편입토지 상세와 공란 보강 상태 확인

핵심 요소:
- 편입토지 목록/카드
- 소재지·지목·면적
- PNU 및 연결 상태
- VWorld 공란 탐지
- 공란 특성정보 일괄 보강
- 수동 fallback

중요 표시:
- 평가서 추출값
- 사용자가 입력한 값
- VWorld 보강값
- 미확인/검토 필요 상태를 시각적으로 분리

### Workflow 3 — 평가논리 검토

목적: 법인별 평가구조와 차이를 검토

핵심 요소:
- 법인별 수치 비교표
- 편입토지↔비교표준지 개별요인표
- 비교표준지↔거래/평가사례 비교표
- 그 밖의 요인 상세
- 역산 감사 상태

모바일:
- 필지별 카드 우선
- 법인 A/B 핵심 수치를 세로 스택으로 표시
- 전체 표는 가로 스크롤 허용

### Workflow 4 — 지장물 및 단가

목적: 현재 구현된 지장물/단가 검토 데이터를 보존하고 접근 가능하게 유지

v0.1에서는 기능 확장보다 기존 stable16 동작 보존이 우선이다.

### Workflow 5 — 쟁점 및 의견서

목적: 분석 결과를 실무 문안으로 연결

핵심 요소:
- 쟁점 후보
- 추가 검토 필요자료
- 주장문 초안
- 리스크 경고
- 제출 전 검토 상태

표현 원칙:
- `쟁점 후보`
- `검토 보조`
- `수동 검수`
- `전문가 검토 필요`

## 3. 개발자 상세 화면

일반 실무 사용 흐름에서 숨기거나 후순위로 두되 삭제하지 않는다.

보존 대상:
- 업로드·JSON 관리
- 원본·추출상태
- OCR 검수 작업대
- 문서해석 작업대
- 편입토지 상세
- 공적자료 상세
- 표준지·사례 상세
- 필지별 단가 상세
- 편입토지↔표준지 상세
- 표준지↔사례 상세
- 그 밖의 요인 상세
- 쟁점 상세
- 문안 상세
- 리스크 상세
- JSON/API/OCR 관리

## 4. 핵심 상태 시각화

### 확인 완료

의미: 원문 또는 명시적 검수로 확인된 값

### 보강 필요

의미: 공란 또는 외부자료 확인이 필요한 값

### 검토 필요

의미: OCR, 역산, 복수 후보, 모호성 등으로 자동확정 금지

### 정보

의미: 출처·연도·상태 등 참고 메타데이터

### 미입력

의미: 값이 없으며 추정하지 않음

## 5. 지도 화면

지도는 별도 장식 화면이 아니라 다음 비교에 사용한다.

- 편입토지↔비교표준지
- 비교표준지↔사례
- 도로·접근성
- 지목/현황 차이

브라우저 미리보기와 최종 QGIS 출력의 검증수준을 구분한다.

## 6. 결과 출력

v0.1 결과 화면은 최소 다음을 한 흐름에서 확인 가능해야 한다.

1. 대상토지 기본정보
2. 법인별 평가수치
3. 개별요인 비교
4. 그 밖의 요인 비교
5. 지도
6. 쟁점 후보
7. 주장문 초안
8. 리스크 경고

## 7. 반응형 종료기준

### 모바일 390px급

- 핵심 버튼 화면 밖 이탈 없음
- 카드 텍스트 잘림 없음
- 상태칩 겹침 없음
- 대형 표는 가로스크롤 또는 카드 전환
- 쟁점/문안은 본문폭에 맞게 줄바꿈

### 태블릿 768px급

- 1~2열 카드 자연스러운 재배치
- 주요 비교값 동시 확인 가능

### 데스크톱 1440px급

- 좌측 내비게이션과 본문 병행
- 비교표·상세카드의 정보밀도 유지

## 8. v0.1에서 하지 않을 화면 작업

- 전면 리디자인
- React/Vue 전환
- 신규 디자인 시스템 도입
- 애니메이션/장식 중심 개선
- 기존 `data-section` 이름 변경
- stable16 렌더 함수 삭제
