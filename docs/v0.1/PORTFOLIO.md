# 보상전략 OS v0.1 포트폴리오 설명문

## 프로젝트 한 줄 소개

**보상전략 OS**는 토지보상 감정평가서의 반복적인 분석·비교·검토 과정을 구조화해, 평가서 원문을 의견서 작성 가능한 검토자료로 전환하는 AI·데이터 기반 실무 자동화 MVP입니다.

## 문제 정의

토지보상 실무에서는 한 건의 감정평가서를 검토하기 위해 편입토지, 비교표준지, 거래/평가사례, 개별요인, 그 밖의 요인, 평가법인별 단가와 금액을 여러 페이지에서 반복적으로 찾아 비교해야 합니다.

실무자는 원문을 읽는 데 그치지 않고 다음을 동시에 확인해야 합니다.

- 어떤 비교표준지가 사용됐는가
- 편입토지와 표준지의 특성이 어떻게 비교됐는가
- 거래/평가사례가 어떤 구조로 연결됐는가
- 법인별 개별요인과 그 밖의 요인이 얼마나 다른가
- 공적자료나 지도에서 추가 확인해야 할 부분이 있는가
- 의견서에서 검토할 쟁점 후보는 무엇인가

이 과정은 전문성이 높고 반복량이 많지만, 단순 OCR이나 문서요약만으로는 해결되지 않습니다.

## 해결 방식

보상전략 OS는 감정평가서의 문서 구조와 보상평가 산식을 하나의 워크플로로 모델링했습니다.

1. PDF 업로드 및 로컬 텍스트/OCR 추출
2. 편입토지·비교표준지·사례·평가행 구조화
3. 평가법인별 공시지가·시점수정·개별요인·그 밖의 요인·단가·금액 비교
4. 평가서에 없는 토지특성은 VWorld 등 공적자료로 보강하되 원문값과 출처를 분리
5. 편입토지↔표준지, 표준지↔사례 관계를 표와 지도에서 검토
6. 쟁점 후보와 의견서 주장문 초안을 생성
7. 제출 전 표현·데이터·개인정보 리스크를 점검

## 핵심 설계 원칙

### 1. AI가 판단자가 되지 않도록 설계

시스템은 보상금 증액 가능성, 적정 보상액, 법률적 승패를 자동으로 확정하지 않습니다.

출력은 다음 수준으로 제한합니다.

- 쟁점 후보
- 추가 검토사항
- 비교자료
- 의견서 작업용 초안
- 리스크 경고

### 2. 원문과 추론을 분리

OCR 결과, VWorld 보강값, 역산값은 감정평가서 원문값과 같은 데이터로 취급하지 않습니다.

예를 들어 산식을 이용해 역산한 값은 `REVERSE_INFERENCE`로 표시하고, 원문에 없는 개별요인 세부항목을 생성하는 데 사용하지 않습니다.

### 3. 모호하면 자동확정하지 않음

PNU가 없거나 복수 후보가 존재하거나 표준지 연결이 모호하면 시스템이 임의 선택하지 않고 `REVIEW_REQUIRED` 또는 `BLOCKED` 상태로 남깁니다.

### 4. 개인정보 로컬 우선

실제 평가서, 비밀번호, API Key, 상세주소, PNU, 실거래 원자료를 저장소에 보관하지 않는 구조를 우선했습니다. 회귀테스트는 합성·비식별 fixture를 사용하고 개인정보 유입을 차단하는 CI를 두었습니다.

## 구현 범위

- 정적 HTML 기반 모바일/데스크톱 검토 UI
- PDF.js 기반 텍스트 추출
- 선택 OCR 검수 흐름
- 감정평가서 Parser 및 canonical JSON
- 편입토지·표준지·사례 연결
- 법인별 평가수치 비교
- 개별요인/그 밖의 요인 검토
- VWorld 토지특성 보강
- 거래사례 특성 enrichment
- PNU/출처/연도 fail-closed 검증
- 지도 검토 및 QGIS 출력 파이프라인
- 쟁점 후보·주장문 초안·리스크 구조
- 회귀테스트 및 개인정보 CI

## 검증 사례

개발 과정에서는 합성 fixture뿐 아니라 비공개 로컬 환경의 실제 평가서와 실제 공적자료를 사용해 end-to-end 검증을 수행했습니다.

검증은 단순히 화면이 열리는지 확인하는 방식이 아니라 다음을 대상으로 했습니다.

- 원문 수치와 Parser 결과 일치 여부
- 편입토지와 평가행 연결
- 비교표준지/사례 연결
- 산식 정방향 검산과 역산값의 출처 분리
- PNU exact-one
- 지도 출력
- 개인정보와 API Key의 저장소 유입 여부

공개 포트폴리오에서는 실제 사건을 재식별할 수 있는 이름·지번·금액·원문 이미지를 사용하지 않고 합성/비식별 데모로 대체합니다.

## 프로젝트에서 보여주고 싶은 역량

이 프로젝트의 핵심은 AI 모델 자체를 만든 것이 아니라 **토지보상 실무자의 판단과 검토 순서를 데이터 구조와 자동화 흐름으로 번역한 것**입니다.

보여주는 역량은 다음과 같습니다.

- 토지보상 감정평가서 구조 이해
- 개별요인·그 밖의 요인·비교표준지·거래사례 분석
- 실무 데이터 모델링
- PDF/OCR 자동화
- VWorld·공적자료 연동 설계
- QGIS/지도 시각화
- Excel/JSON/Python/JavaScript 기반 반복업무 자동화
- 개인정보·출처·모호성에 대한 fail-closed 설계
- AI 결과를 전문가 검토 흐름에 배치하는 제품 설계

## 프로젝트의 한계

보상전략 OS는 감정평가법인의 평가업무, 변호사의 법률판단 또는 전문가의 최종 검토를 대체하지 않습니다.

또한 v0.1은 상업용 SaaS가 아니라 내부 실무 자동화와 이직 포트폴리오를 위한 MVP입니다. 멀티테넌시, 보상금 예측, 자동 법률자문, 개인정보 원문 클라우드 저장 등은 의도적으로 제외했습니다.

## 포트폴리오 발표용 요약

> 토지보상 실무를 오래 수행하면서 가장 반복적이고 검토부하가 큰 감정평가서 분석 과정을 자동화해 보았습니다. 단순 OCR이나 요약기가 아니라 편입토지, 비교표준지, 거래사례, 개별요인, 그 밖의 요인, 법인별 평가수치를 구조화하고 공적자료와 지도까지 연결하는 검토 시스템입니다. 중요한 설계 원칙은 AI가 보상액이나 법률판단을 확정하지 않도록 하는 것이었습니다. 원문, OCR, 외부 API, 역산값의 출처를 분리하고 모호한 경우 자동확정하지 않는 방식으로 실제 전문가 검토 흐름에 맞췄습니다.
