## 1. 표준지 자료 원천

| 모드 | 원천 | 범위 |
|---|---|---|
| 합성 | 합성 표준지(VWorld 필드 이름 형태, 값 전부 가상) | 같은 법정동 |
| VWorld 직접 | `ned/data/getReferLandPriceAttr`(표준지공시지가 속성조회) JSONP, `ldCode`=PNU 앞 10자리, 기준연도, 100행×최대 3쪽 | 같은 법정동 |
| 로컬 브리지 | 미지원(`NOT_SUPPORTED`) | — |

- 범위 확대(인접 법정동)는 자동으로 하지 않는다. 후보가 없으면 "표준지 후보 미확보"와 함께 범위 판단을 전문가에게 남긴다.
- 거리: 후보(최대 10건)만 지적 도형(`LP_PA_CBND_BUBUN`) 중심점으로 계산. 호출 수를 줄이려 배제 표준지는 거리 미산출일 수 있다.
- **2026-11-23 실호출(GPT, ThinkPad, 공공청사 표본 법정동)**: `getReferLandPriceAttr` 2025·2026 각 HTTP 200·JSONP 정상·root `referLandPrices`·연도별 7행.
- 실스키마 차이 수정: 표준지 용도지역은 **`prposAreaNm1`**, 보조 용도지역은 **`prposAreaNm2`**(토지특성 API의 `prposArea1Nm`/`prposArea2Nm`과 다름). 표준지 매핑은 실스키마 우선, 토지특성 계열 이름은 별칭으로 보존.
- 안전장치: 용도지역·이용상황·공시지가·기준연도·PNU 중 하나라도 응답 전체에서 해석되지 않으면 '미기재'로 전부 배제하지 않고 `SCHEMA_UNMAPPED`(판정 보류)로 멈추고 응답 필드 이름을 표시한다.
- 빈 값은 "확인 필요"로 둔다(외부 사례상 일부 행의 지세·형상·도로접면이 빈 문자열).
- 조회 범위 한계: 같은 법정동 표준지만 비교한다. 인접 법정동·주위환경이 유사한 다른 지역 표준지가 빠질 수 있음을 후보 목록·의견 ②에 항상 표시한다.

## 2. 후보 선정 규칙 (`core/standard-land-engine.js`)

1. 같은 PNU·연도 중복 행은 토지특성과 같은 규칙(`core/ned-revisions.js`)으로 정리, 값 충돌이면 배제
2. 배제: 기준연도 불일치 · 공시지가 미기재 · 용도지역 미기재/상이 · 이용상황 미기재/이용상황군 상이
3. 남은 후보 정렬: 일치 항목 수(지목·도로접면·형상군·지세·용도지구·이용상황) → 거리
4. 상위 3건만 후보, 나머지는 "유사 후보 3건 초과"로 배제 목록에 표시
5. **가장 가까운 표준지가 배제되면 별도 표시**(거리·사유). 후보는 "확정 아님"

## 3. 8개 가격형성요인 비교

| 요인 | 확인된 자료 | 우열 가설(자료 있을 때만) | 확인 필요 |
|---|---|---|---|
| 용도지역 | 대상·표준지 용도지역 | — | — |
| 이용상황 | 이용상황·이용상황군 | 같은 군·다른 세부 → 차이 검토 | 실제 이용상황 현장 |
| 주변환경 | 표준지 주위환경 기재(있으면) | — | 대상 주위환경 지도·현장 |
| 가로조건 | 도로접면 | 등급 차 1 이상 → 대상 열세/우세 가능 | 도로 폭·포장·계통 |
| 접근조건 | 대상↔표준지 직선거리 | — | 교통·생활시설 접근성 |
| 환경조건 | 없음 | — | 일조·소음·혐오시설 |
| 획지조건 | 면적·형상·지세 | 규모 3배 이상, 정형↔부정형, 평지↔경사·저지(임야 제외) | 실측·출입 |
| 행정적 조건 | 용도지역·용도지구 | 용도지구 기재 차이 → 차이 검토 | 토지이용계획확인원 |

## 4. 상담 초동의견 (`core/consult-opinion.js`)

① 대상토지 주요 특징 ② 비교표준지 검토 ③ 향후 주장 가능 쟁점(후보) ④ 추가 확보자료·상담 멘트

- 모든 항목은 근거 필드에 연결. 쟁점은 근거가 있을 때만 생성(현실적 이용상황, 가로조건, 획지조건, 행정적 조건, 비교표준지 선정 적정성, 연도 간 특성 변경)

- 합성 결과는 "[합성 시연자료]"·"(시연자료 기준)" 표시
