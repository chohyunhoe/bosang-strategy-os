## 1. P0 지적경계 일부만 표시 — 수정
**원인(QA 지적과 일치):** `parcel_map`이 대상 중심 고정 BBOX(±0.005°)를 VWorld `size=100`으로 1회만 조회했다. 그래서 화면 이동·줌과 무관했고 100건 초과분은 버려졌다.

**수정 방식**
- **조회 단위:** 0.01° 고정 격자 칸. 기존 검증된 BBOX 상한 0.01°를 해제하지 않고 칸으로 나눈다.
  - 화면(1024×768 영상 범위)에 걸친 칸만, 중심 칸부터 조회한다.
- **페이지 조회:** 칸마다 `size=1000`·`page=1..3`으로 `record.total`까지 받는다.
  - **실측 1회(2026-11-25, PC):** 궁평리 320-1 칸 `BOX(127.31,36.62,127.32,36.63)`.
  - 결과: `size=1000` 허용, `record.total=884`, `page.total=1`, 응답 약 0.8MB. 키·좌표 원문은 출력하지 않았다.
- **칸 상태(서버 판정)**

  | 상태 | 조건 |
  |---|---|
  | `COMPLETE` | 받은 건수 = `record.total` |
  | `PARTIAL` | 페이지·호출 예산 상한으로 일부만 받음 |
  | `COUNT_UNKNOWN` | 건수 메타 없음 — 완전으로 표시하지 않음 |
  | `FAILED` | 조회 실패 |
  | `NOT_QUERIED` | 예산 초과로 조회하지 않음 |

- **화면 표시**
  - `COMPLETE`가 아닌 칸은 지도에 **빗금**과 노란 점선으로 표시한다(지적선이 없어도 필지가 없는 것이 아님).
  - 지도 아래 상태줄에 `지적 전체(화면)` / `지적 일부 · n/m칸`을 보인다.
  - 칸별 `받은/전체 건수`·사유는 '출처·검증 상세'에 있다.
- **호출 통제**
  - 첫 화면은 중심 칸부터 **최대 4칸만 자동** 조회한다.
  - 줌·'필지 중심'↔'후보 비교' 전환은 **자동 조회하지 않는다.**
  - 상담자가 **'현재 화면 지적 불러오기(n칸)'**를 누르면 화면 칸만 조회한다(클릭당 9칸, 요청당 4칸).
  - 상한
    - 요청당 VWorld 8회·응답 6MB. 실행 중 서버의 브리지 출력 상한 8MB를 넘지 않게 했다.
    - **상담당 40회.** 넘으면 '지적 조회 한도(이번 상담)'로 표시하고 더 부르지 않는다.
  - 받은 칸은 같은 상담 안에서 캐시한다. 실패 칸만 재시도하고, 일부(상한) 칸은 반복 호출하지 않는다.
- **정합·표시 규칙**
  - 칸 경계에 걸친 필지는 PNU로 중복을 제거한다. 화면 밖 지적은 그리지 않는다.
  - 대상 빨간 경계(같은 PNU exact-one)·후보 ①②③ 위치·영상 정합은 변경하지 않았다.
  - 지적선을 지어내지 않는다.
- **하위 호환:** 기존 `{pnu, neighbors:true}` 경로 코드는 그대로다. 운영 중인 페이지(이전 빌드)의 동작은 변하지 않는다.
  - 새 페이지는 대상 경계 조회(`{pnu}`)와 칸 조회(`{pnu, tiles}`)를 나눠 부른다.
  - 같은 허용 작업 `parcel_map`이라 서버 허용 목록 변경도 필요 없다.
