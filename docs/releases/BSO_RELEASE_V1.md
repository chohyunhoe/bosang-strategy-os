# BSO Release v1 — Windows PC

기준일: 2026-11-04 · 버전: `1.0.0-rc.4`

현재 상태: `PC_RELEASE_CANDIDATE / REAL_CASE_REVIEW_PENDING`

기존 Product v2.1 코드에서 실무용 Release v1을 빌드한다. 제품 릴리즈명과 내부 런타임 버전은 별개다. 기존 Cloudflare 배포 및 v2.1 릴리즈는 자동 변경하지 않는다.

## 실행과 종료

1. 저장소 루트의 `RUN_BSO.cmd`를 더블클릭한다.
2. `http://127.0.0.1:4174/`가 열린다. 실행 창은 작업 중 열어 둔다.
3. 평가서를 등록하고, 보류 문서와 전체 검수 항목을 원문과 대조한다.
4. 종료 전에 홈의 **사건 저장**으로 JSON을 안전한 로컬 위치에 보관한다.
5. 다음 실행에서 **사건 불러오기**로 이어서 작업한다. PDF 원본과 API 키는 다시 선택한다.

최초 설치 조건은 Windows PowerShell, Node.js 22 이상(24 권장), 프로젝트 Node 의존성이다. 의존성이 없으면 런처가 `npm ci`를 실행한다. Python이 없어도 PDF/OCR·검수·사건 JSON 저장과 VWorld API 빠른지도 화면은 실행된다. DOCX/XLSX/CSV 결과물에는 Python 3.10 이상과 보고서 모듈이 필요하다.

보고서 구성요소 준비는 `SETUP_BSO_OUTPUT.cmd`로 실행한다. 이 단계는 `.venv-v1`을 준비하고 `brief_output/requirements.txt`의 패키지를 설치한다. 기존 `.venv`는 삭제하지 않는다. 설치에는 인터넷 연결이 필요하다.

`BSO_NODE`, `BSO_PYTHON` 환경변수로 실행 경로를 지정할 수 있다. 컴퓨터별 경로가 필요하면 git 제외 파일 `.bso-runtime.json`에 `node`, `python` 경로만 넣는다. API 키를 이 파일에 넣지 않는다.

## v1 업무 범위

- 복수 평가서 PDF 등록, TEXT 추출 및 한국어/영어 로컬 OCR
- 법인별 원장·토지·표준지·사례·개별요인·지장물 검토
- 원문 근거, 값 수정, 검수 확인·보류
- VWorld 빠른지도, 필지·표준지·사례 관계도 및 PNG
- 분석보고서 DOCX, 수치표 XLSX/CSV, 의견서 작성자료 DOCX
- 다중 사건 전환, 명시적 로컬 JSON 저장·복원
- 현장 사전분석키트와 기존 업무도구 유지

VWorld API 키·공공데이터 키·QGIS 정밀도면 환경은 해당 기능에만 필요하다. QGIS·로컬 지적원본이 없다는 이유로 앱 전체를 중단하지 않는다. 현재 탭의 사건 데이터는 자동 영구저장하지 않는다. JSON 백업은 원문 PDF·키를 제외하지만 주소·PNU·금액·원문 발췌가 포함될 수 있다.

## 보류 문서 처리

홈에서 **보류 문서 원문·추출 확인**으로 이동하면 사건 화면에 문서별 이유가 나온다.

- 평가법인명 미식별: 원본 표지 등을 확인하고 **평가법인 → 원문·수정**에서 입력한다. 해당 법인명 보류만 해소하며 검수완료를 자동 처리하지 않는다.
- 표준지 열 밀림·관계 불일치 등 다른 보류: 계속 보류한다. 원본 교체·재추출과 원문 대조가 필요하다.
- 처리 중에는 새 사건·다른 사건 열기·삭제·백업 불러오기를 막는다.
- 보류 문서는 지도 입력에서 제외한다. 보류 사건을 저장·복원해도 보류 상태를 유지한다.

현재 로컬 PDF 3건을 사용한 기존 다중문서 강한 인수검사는 평가법인명 자동 식별 조건을 충족하지 못했다. 이 결과를 통과로 바꾸지 않았다. 사용자 원문 확인 없이 파일명만 보고 법인명을 만들지 않는다.

실제 PDF 정답 검사는 `BSO_V1_ACCEPTANCE_A_PDF` 및 `BSO_V1_ACCEPTANCE_EXPECT`에 로컬 파일을 지정하고 `release_v1_local_pdf.spec.js`를 실행한다. 정답 JSON은 `lands`, `standards`, `cases`, `results`, `obstacles`, `landSum`, `obstacleSum`, `auto` 집계 필드를 사용한다. 원문·정답 파일은 커밋하지 않는다.

## RC2 혼합 이미지 평가서 필지 인식 수정 (2026-11-04)

- 본문 텍스트가 충분해도 텍스트가 적은 이미지 페이지는 개별 OCR 대상으로 선택한다.
- 여백이 큰 표는 데이터 영역을 확대 OCR하며, 영역 밖 주소와 명시 지번 하이픈을 보존한다.
- 독립 테두리 기호, 띄어진 표제, 줄바꿈 주소 및 0을 채운 지번을 구조적으로 정리한다.
- 산출근거표만으로 별도의 편입토지를 만들지 않는다. 판독되지 않은 지목·주소·수치는 추정하지 않는다.
- 추출 보류 사건은 기존 검수그룹을 확인해도 출력 메타데이터를 REVIEWED로 만들지 않는다.
- 로그에 선택 OCR 장수, 표 확대 완료 및 문서별 파싱 집계·첫 보류 코드를 추가한다. 원문·주소·금액은 기록하지 않는다.
- 사용자 원문 4건을 로컬 전용 입력으로 재현했다. 필지 인식 실패는 문서 전체 텍스트 양으로 이미지 표 OCR을 생략하던 조건에서 시작됐다.

- 같은 원문 4건을 실제 PDF 업로드·OCR로 처리하여 고유 필지 3건을 복구했고, 원문 면적과 대조했다. 원문 및 OCR 페이지는 로컬 임시자료로만 유지한다.
- 산출표의 산정단가·적용단가를 단가·보상총액으로 오인하던 행은 계수열과 끝단 단가쌍을 함께 확인해 제외한다. 금액 열이 명시된 표는 이 판정을 적용하지 않는다.
- 법인별 평가행 일부는 여전히 누락되거나 금액 미식별 상태다. 필지 인식 복구를 전체 금액 추출 완료로 취급하지 않으며, 자동확정 없이 원문 검수를 유지한다.
- RC2 파서 전체·릴리즈 무결성 회귀 통과. 실제 OCR 결과의 브라우저 재처리에서도 동일한 고유 필지 수와 면적, 자동확정 차단을 확인했다.


## RC3 법인별 평가행·금액 복구 (2026-11-04)

- 토지평가조서의 연번·지번·가격 위치가 확인된 행을 별도로 확대 OCR한다. 기존 주소·지목 셀은 보존한다.
- 확대 OCR에서 직접 읽은 단가·금액만 사용하고, 같은 연번·지번·면적과 명시 지분의 산술 관계를 대조한다. 누락 금액을 계산해 채우지 않는다. 기존에 명확히 읽힌 금액·지분은 덮어쓰지 않는다.
- 소재지 셀이 손상된 조서 행은 인접 페이지의 같은 연번·정규화 지번에 유일하게 명시된 법정동으로 연결하며 원문 출처를 함께 보존한다. 다른 지번 후보나 충돌 주소는 복구하지 않는다.
- 관련 회귀시험은 합성 입력으로 작성하며 실제 PDF·금액·주소는 커밋하지 않는다.

- 표지 법인명은 법인명 영역의 완전한 OCR 기재를 우선 보존한다. 미추출 수치는 0 대신 공란 기호로 표시한다.
- 긴 평가사유 설명 셀이 OCR 계수열에 끼면 개별요인·그 밖의 요인 열을 임의 배정하지 않고 검수 대상으로 남긴다. 직접 읽은 단가·금액은 보존한다.

- 동일한 원문 PDF 4건을 실제 브라우저 업로드·OCR로 반복 처리했다. 최종 결과는 고유 필지 3건, 문서별 평가행 2·2·1·1건(합계 6건)이며 단가·금액·지분 및 법인명을 로컬 원문 대조값으로 확인했다. 평가행·단가·금액 누락은 0건이다.
- 최종 파서로 실제 OCR 페이지를 재처리하고 검수 화면의 6개 금액, CSV 실제 출력, 결과물 전달 데이터 및 사건 JSON의 저장·복원 값 일치를 확인했다. 자동확정은 없고 검수 상태를 유지한다.
- 전체 파서·브리지·릴리즈 무결성 검사 통과. PC Chromium 회귀 70건 통과, 별도 원문·모바일 등 조건부 검사 9건 제외. 원문을 지정한 이번 4건 검증은 해당 제외 항목과 별도로 수행했다.
- 이 검증은 제공된 PDF의 평가행·단가·금액·지분 인식 범위다. 미식별 세부요인 계수, 실제 VWorld 인증·지도 범위 및 제출 보고서 검토는 담당자 원문 검수 대상으로 유지한다. 정식 운영 배포나 원격 CI 완료를 의미하지 않는다.


## RC4 OCR 금액 복구 안전성 보완 (2026-11-04)

- RC3의 공개 PR 검토와 최신 소스에서 면적이 금액으로 대체되는 오류 및 명시 지분 충돌을 합성 입력으로 재현한 뒤 수정했다.
- 금액 위치는 면적·지분 표현 다음의 정확히 두 정수 셀로 제한한다. 면적이 1,000 이상이거나 금액 한 칸이 판독 불가인 경우 면적을 금액 후보로 사용하지 않는다. 금액 위치가 모호한 행은 원문을 보존한다.
- 원문의 명시 지분은 쉼표 유무와 무관하게 독립 대조한다. 충돌 지분과 이미 읽을 수 있는 명시 지분·금액 행은 자동 대체하지 않고 원문 검수 대상으로 남긴다. 누락 금액을 계산해 채우지 않는다.
- 회귀시험은 공개 합성 데이터만 사용한다. 기존 주소·지목·면적, 보류·검수 경계와 stable16 기능은 유지한다.
- 이번 판올림은 코드·릴리즈 후보 보완이다. RC3에서 보고된 실제 PDF 4건의 로컬 검증을 RC4의 새 실기검증으로 재사용하지 않는다. Windows 실제 원문 대조, VWorld 인증·지도 범위와 제출 보고서는 별도 확인한다.
- RC4 클라우드 검증: 금액 복구 합성 회귀 23건, 전체 `test:rc`, v1 빌드·파일 무결성·보류 복원, 전체 JavaScript 문법, 개인정보 검사(531개 추적 텍스트/경로) 통과. Chromium E2E는 브라우저 시작 단계의 시스템 소켓 권한 제한으로 실행 차단됐다. E2E 통과로 취급하지 않는다.

### RC4 실무 안전성 후속 보완 (2026-11-04)

- 추가 평가서를 읽거나 검수 대상의 내용을 수정하면 변경된 그룹의 기존 검수완료 결정을 해제한다. 새 행은 이전 법인의 검수 시각을 물려받지 않는다. 변경 없는 그룹의 결정과 기존 보류 메모는 유지한다. 출력에서도 현재 검수큐·완료 가능 여부·행 수를 다시 확인한다.
- 동·리와 지번만 같다는 이유로 상위 행정구역 또는 명시 PNU가 다른 토지를 병합하지 않는다. 축약 주소는 유일한 호환 후보에만 연결하고, 기존 주소 근거를 모두 보존한다. 같은 PNU라도 면적·지목이 다른 행은 자동 통합하지 않는다.
- 지도 결과를 생성 당시 사건과 입력에 연결한다. 사건 전환·복원·지도 입력 변경 시 이전 결과를 폐기하며, 늦게 끝난 API·QGIS 응답과 PNG 작업이 다른 사건의 의견서에 섞이지 않게 차단한다. 같은 사건의 정상 지도 출력은 유지한다.
- 원문에 정수 배율과 단가·금액이 있고 산술적으로 일치하면 확대 OCR의 다른 지분 후보로 덮어쓰지 않는다. 기존 손상 지분의 검증된 복구 경로는 보존한다.
- 후속 최종 코드에서 전체 `test:rc`, 릴리즈 빌드·무결성·복원 검사, 개인정보 검사(535개 추적 텍스트/경로)를 통과했다. 현재 클라우드의 Release v1 Chromium 검사는 71건 통과·기존 조건부 9건 제외다. 초기 RC4의 브라우저 시작 차단 기록과 구분한다. 합성 회귀 및 기존 출력 bridge 검증이며 실제 PDF 4건의 신규 재실행은 아니다.
