# LK 문서 진행관리 1차 구현

## 범위와 상태

2026-11-05 기준 개발 범위는 기존 BSO 결과물 화면의 수동 문서 진행관리다.
문서 종류와 관계없이 용도·독자, 담당자, 기준 서식·버전, 원본 참조를 등록한다.
감정평가 파서·지도·수치 비교·출력 기능은 유지한다.

이 기능은 문서의 실제 내용이나 파일 존재를 검사하지 않는다.
검수·승인·제출은 사용자가 직접 입력한 기록이며, 직원 신원이나 변호사 자격을 인증하지 않는다.
전 직원용 운영 인증·권한·결재 시스템으로 사용하려면 별도의 서버 기반 구현이 필요하다.

## 동작

1. `쟁점·결과물` → `문서 진행관리`에서 문서를 등록한다.
2. 원본·수치·법률·서식 항목마다 기록자와 근거를 입력한다.
3. 네 항목의 기록이 있어야 승인 기록, 그 뒤 제출 기록을 추가할 수 있다.
4. 수정본 시작 시 버전이 증가하고 현재 검수·승인·제출 상태를 해제한다. 이전 이력은 보존한다.
5. 후속조치는 담당자·기한·근거를 기록하고 완료 근거를 별도로 남긴다.
6. 제출 기록이 있고 미완료 후속조치가 없으면 해당 문서의 기록상 진행 상태만 DONE이다.

위 DONE은 파일의 정확성·실제 발송·실제 업무 종결을 시스템이 검증했다는 뜻이 아니다.
인증 없는 JSON 기록은 위변조 방지 감사로그가 아니다.

## 보관·호환성

- 현재 브라우저 메모리와 기존 사건 JSON 저장·불러오기를 사용한다.
- 문서만 등록한 사건도 미저장 경고 대상이다.
- 사건 전환 시 문서 상태를 분리하며, 새 사건은 빈 목록으로 시작한다.
- 이전 백업에 문서 필드가 없어도 불러올 수 있다.
- 잘못된 상태·검수 근거·버전·후속조치가 있는 백업은 현재 상태를 교체하기 전에 거절한다.
- 자동 서버 저장, 외부 AI 전달, 실제 발송, 파일 본문 저장은 수행하지 않는다.
- 원본 참조·승인메모에 개인정보를 입력할 수 있으므로 사건 백업은 승인된 위치에 보관한다.

## 검증

- `node tests/document_workflow.test.js`: 단계 건너뛰기 방지, 수정 무효화, 완료 근거, 기한, 사건 분리, 백업 호환·원자적 거절.
- `npm run product:v2:test`: 기존 제품 테스트와 위 테스트.
- `npm run product:v2:e2e`: 브라우저에서 등록·단계 전환·수정·사건 분리·HTML 이스케이프.

## 다음 개발 게이트

1. 실제 문서 1건의 작성→검수→변호사 검토→제출→회신 흐름 검증.
2. 생성 산출물의 파일 식별자·해시와 검수 기록 연결.
3. 부서·사건별 권한과 인증된 승인자, 서버 저장·감사로그.
4. 권한과 전송 범위가 확인된 작업부터 외부 AI·자동화 실행 연결.

세션 분석의 출발점은 사용자 개인의 토지보상 업무다. 다른 부서의 실제 업무가 검증된 것으로 해석하지 않는다.
