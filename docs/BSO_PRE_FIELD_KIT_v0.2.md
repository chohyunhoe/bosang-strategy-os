# BSO Pre-Field 사전분석키트 v0.2.1

기준일: 2026-09-11 (v0.1 기준일 2026-09-10) · 적용 역량: M3 공간·현장 증거화 / M5 쟁점·반박 설계

## 1. 결론 및 역할 분리

신규사업 모니터링에서 `현장검토 필요`로 선별된 사업을 현장 방문 전에 1~2페이지로 정리하는
기능을 기존 BSO 업무도구 화면(`지도·현장`) 안에 추가했다. 신규 시스템·신규 대시보드는 만들지 않았다.

| 단계 | 역할 | 출력 |
| --- | --- | --- |
| 신규사업 모니터링(나라장터 EARLY_SIGNAL) | 발견·선별 | 모니터링 행, 상태 `확인 필요` |
| BSO Pre-Field 사전분석키트 | 현장 실행용 분석 | Snapshot·Target Map·접촉거점·쟁점·Field Mission |

키트는 판정하지 않는다. 편입·보상대상, 보상금액, 증액 가능성, 수임 가능성을 결론으로 쓰지 않는다.

## 2. 구성 (P0)

1. **사업 Snapshot** — 사업명·시행자·사업단계·면적·사업비·주요 일정·보상 예상시점.
   각 항목은 `SOURCE_STATED` / `EARLY_SIGNAL_PENDING_REVIEW` / `INPUT_WITHOUT_SOURCE` / `UNVERIFIED`
   중 하나로 표시한다. 값이 없으면 `미확인`과 확인방법만 남기고 추정값을 만들지 않는다.
   사업단계만으로 보상시점을 추정하지 않는다.
2. **경계·Target Map** — 사업경계 적재상태와 주변 도로·마을·상권·공장 등 공간구조,
   그리고 방문 후보 타깃. 타깃은 종류로 구분한다.
   지역·거점(`AREA`)은 마을·상가 밀집부, 생활권 진입·간선 동선, 행정·주민조직 거점이고,
   시설·필지군(`FACILITY`)은 특수이용, 대규모 편입후보, 상업·공업 이용지, 시설 밀집 구간 후보이며,
   사건 필지(`CASE`)는 건축물 편입, 도로접면 변화, 동일소유자 다필지, 경계절단이다.
   각 타깃에는 근거, 근거등급(`DATA_SOURCED`/`BSO_ESTIMATE`), 전제조건, 확인질문, 현장 확인사항이 붙는다.
   근거등급은 입력자료의 출처 등급이며 타깃 판정은 모두 `judgment_status=FIELD_VERIFICATION_REQUIRED`다.
   필지 도형자료가 없으면 경계절단을 판정하지 않고 확인 필요 항목으로 남긴다.
3. **접촉거점** — 마을회관·대책위 장소·상인회·중개업소·주민센터·현장사무소 등 장소·단체만 담는다.
   인물 유형 입력은 채택하지 않고, 연락처·이메일·성명 필드는 제거한 뒤 제거 사실을 기록한다.
4. **쟁점** — `[확인쟁점]`은 출처가 있고 대응 필요성이 있는 항목만 채택한다. 출처 없는 입력은
   `SOURCE_MISSING_NOT_CONFIRMED_ISSUE`, 단순 사업현황은 `PROJECT_STATUS_NOT_ISSUE`로 반려하고
   Snapshot 후보(`snapshot.status_candidates`)로 돌린다. `[BSO 추정쟁점/현장검증 필요]`는
   근거·현장 확인사항·전제조건을 함께 가진다. 전제가 확인되지 않으면 승격하지 않고
   `[현장확인 필요 · 전제 미확인]`(`FIELD_CHECK_REQUIRED`)으로 강등한다.
0. **현장카드(v0.2.1)** — 출력 맨 위에 둔다. 오늘의 목표, 방문 동선, 핵심 질문,
   오늘의 종료기준만 담는다. 출처·근거등급·판정코드는 담지 않고 아래 상세근거에만 남긴다.
   자료 확보 같은 사무 과업은 `출발 전 확인`으로 빼고, 물리적 이동만 `오늘의 방문동선`에 1번부터 싣는다.
   질문은 거점·타깃·자료확보 질문에서만 뽑는다.
   새 분석은 하지 않는 출력계층이며, 오늘의 종료기준은 사업단계에 맞춘 한 줄이다.
5. **Field Mission** — 1차 방문 행동 3~5개. 각 Mission 은
   `방문장소 → 방문순서 → 목적 → 확인질문 → 현장확인사항 → 종료기준` 구조를 갖는다.
   거점·타깃·쟁점 데이터를 재사용하며, 찾아갈 수 있는 거점을 먼저 배치한다.
   장소를 모를 때에도 '사업지 일원' 같은 일반 문구로 끝내지 않고 확인할 창구를 지정한다.
   G1 기본 종료기준은 `핵심인물 1명 이상 접촉 + 연락경로 확보 + 다음 접촉 명분 확보`다.

## 3. 사업단계별 Target 프로필 (v0.2)

Snapshot 의 사업단계 표기에서 프로필을 판정하고 타깃 우선순위를 정한다. 단계를 못 읽으면 `UNKNOWN` 으로 둔다.

| 프로필 | 판정 신호 | 타깃 우선순위 |
| --- | --- | --- |
| `PRE_DESIGNATION` 발표·지구지정 전 | 발표, 후보지, 지정 전, 예정, 선정 | 지역·거점 → 시설 → 사건 |
| `PRE_COMPENSATION` 지구지정~보상 전 | 지구지정, 지구계획, 실시계획, 사업인정, 공람 | 시설 → 지역·거점 → 사건 |
| `COMPENSATION` 보상 진행 | 보상 협의·착수·공고, 감정평가, 수용·이의재결 | 사건 → 시설 → 지역·거점 |

접촉거점을 타깃으로 함께 쓰는 것은 `PRE_DESIGNATION`·`UNKNOWN` 단계뿐이다.
자료가 없으면 타깃을 만들지 않고 `target_map.acquisition_actions`(경계 도면·편입 필지자료·현장선별·지역 거점 확보)로 전환하며, 방문 가능한 확보 행동은 Mission 으로 올린다.

## 4. 입력과 재사용

- 모니터링 결과 행(선택) → Snapshot 후보값. 공고명은 사업명 후보, 발주기관은 시행자 후보로만 쓴다.
- 기존 패널의 사업지 경계 JSON과 현장선별(P1·P4·P5) 결과를 그대로 입력으로 쓴다.
- 사건이 열려 있으면 편입토지 조서를 타깃 판정 입력으로 재사용한다.
  지도와 같은 경계를 쓴다. 승격게이트에서 `PARSE_HOLD` 된 문서의 행은 타깃 판정에 넣지 않는다.
- 공공데이터 API 키가 없어도 키트 생성 자체는 동작한다(입력 범위만 줄어든다).

## 5. 출력 경로

- 화면: `지도·현장` 화면의 업무도구 패널 상단 카드(1~2페이지 분량 제한).
  타깃 8건·거점 6건·쟁점 6건을 넘는 분량은 화면에서 생략하고 초과건수를 표시한다.
- CSV: 기존 업무도구 CSV 저장 경로를 재사용한다(`bso-pre-field-kit.csv`).

## 6. 용어 경계

이 저장소에서 `CONFIRMED`는 사용자 검수완료를 뜻한다. 키트는 출처가 기재된 항목을
`SOURCE_STATED`로만 표시하며, 기재된 출처 자체가 검증되었다는 뜻으로 쓰지 않는다.

## 7. 개인정보 경계

현장 방문 전 개인정보·비공개 정보 수집을 전제로 하지 않는다.
키트에는 성명·연락처를 담지 않으며, Mission 문구도 동의 범위에서 연락경로를 확보하는 것으로 한정한다.

## 9. v0.2 · v0.2.1 에서 고친 것

광명시흥·남양주도심 실사용 검증에서 확인된 세 가지를 고쳤다.
Field Mission 이 장소·순서·질문을 제시하지 못한 문제(P1-2), 추정쟁점이 전제조건 없이 생성된 문제(P1-3),
사업현황을 지역 특수쟁점처럼 취급한 문제(P1-4)이며, 초기 사업단계에서 타깃이 0건이 되던 문제는
사업단계별 프로필(P1-1)로 해결했다.

v0.2.1 은 현장 산출물 검수 결과를 반영했다. 분석 우선순위와 영업 우선순위가 화면에서 뒤집혀
Mission 이 맨 아래에 있었고, 내부 판정코드가 현장정보와 같은 위계로 보였다. 새 기능을 더하지 않고
이미 생성된 데이터를 실행 순서로 압축한 현장카드를 맨 위에 두고, 그 아래를 상세근거로 구분했다.

## 10. 제외 범위

뉴스 자동수집 고도화, CRM, 자동점수화, 신규 대시보드, 디자인 개편은 포함하지 않는다.
