# LK 독립 교차검증 운영 절차

기준일: 2026-11-07. 설계 기준: `LK_n8n_자동교차검증_설계지시서_v1.docx`.
이 모듈은 평가서 해석·수치 비교·쟁점 후보·초안·제출검토 흐름에 검토 증거를 추가한다. 기존 BSO 접수, evidence version 2, `PARSE_HOLD`, 사람 검수 및 제출 상태를 보존한다. 검토 결과는 감정평가나 법률 판단을 대신하지 않는다.

현재 제공 범위와 단계별 증거는 [STATUS.md](STATUS.md)에 기록한다. 비활성 n8n 템플릿과 모의시험만으로 운영 구축 완료를 선언하지 않는다.

## 1. 실행 전 확인

현재 비용 정책은 **`FREE_CREDITS_ONLY`**다. 기존 n8n 자격증명을 재사용하며 새 키를 만들지 않는다. 실제 계정별 무료 크레딧 잔액·유효기간·사용 가능 모델·비용 통화가 확인되지 않았으므로 실제 모델 호출은 `BLOCKED`다. 유료 계정·모델로 자동 전환하지 않는다. 무료 웹 대화 이용 권한은 API 크레딧 증거로 취급하지 않는다.

운영자는 다음을 비밀값 없이 기록한다.

- 실제 호스트, 운영체제, n8n 설치 버전, 실행 방식과 필요한 프로세스.
- 현재 활성 워크플로 ID·버전·활성 상태와 연결 자격증명의 참조. 키·인증 헤더·토큰은 기록하지 않는다.
- 승인된 자료 등급·문서·사업자·처리 목적·예산·보존 기간.
- 사업자별 무료 크레딧 잔액의 확인 시각·만료일·통화, 허용 모델과 가격표 기준일. 잔액을 확인할 수 없는 계정은 호출하지 않는다.
- BSO 계약, 사건 ID, 원본·초안 버전과 SHA-256. 동일 지번·면적·비슷한 이름을 소유자 식별자 대신 사용하지 않는다.

사용자가 제공한 n8n Cloud 주소는 HTTPS 200과 로그인 화면까지 직접 확인했다. 현재 작업 브라우저에 인증 세션이 없으며 관리 API는 인증 없이 401을 반환한다. 주소·비공개 연결 관측은 Git 제외 운영 기록에 남긴다. 관리 로그인 후 설치 버전·플랜·활성 흐름·실제 계정 참조를 읽기 확인하고 변경 전 백업을 만든다.

`hhjo-ThinkPad`의 오프라인 상태는 n8n Cloud 편집기 접속을 막는 조건이 아니다. 별도 Python/SQLite 원장 호스트의 가용성과 n8n Cloud에서의 연결 가능성은 각각 검증한다. 호스트 이전이나 queue mode 도입은 이 변경에 포함하지 않는다.

## 2. 변경 전 백업

1. 변경 대상 워크플로를 실제 n8n에서 내보내 비공개 운영 백업에 보관한다. 설치 버전, 워크플로 ID·버전·활성 상태·백업 시각을 함께 기록한다.
2. 자격증명은 n8n 또는 관리형 비밀 저장소의 보호된 백업 절차를 사용한다. 복호화된 자격증명 내보내기나 Git 저장을 하지 않는다.
3. runner와 디스패처를 중지한 뒤 영속 원장을 일관된 방식으로 백업한다. SQLite가 가동 중이면 SQLite 백업 기능을 사용한다. WAL 파일을 제외한 DB 파일 복사를 안전한 백업으로 간주하지 않는다.
4. 원본 manifest·산출물·응답·호출 영수증·비용 대장의 식별자와 SHA-256을 대조한다. 사건 원문과 응답은 저장소에 추가하지 않는다.
5. 기존 접수·승인·결과 이력을 보존한다. 백업 위치는 접근 제한된 운영 기록에 남긴다. 현재 실제 호스트 백업은 미확인이다.

## 3. 설치와 기동

저장소의 검토 브랜치와 테스트 결과를 먼저 확인한다. 기존 워크플로를 대체하거나 기존 브라우저 저장 데이터를 이관하지 않는다. Python runner와 n8n 템플릿은 독립 모듈로 추가한다.

저장소 루트에서 실행한다. runner와 시험은 Python 표준 라이브러리를 사용한다. 먼저 보호된 서비스 런처에서 32자 이상의 임의 공유 비밀값을 `LK_CROSS_REVIEW_TOKEN` 환경변수로 주입한다. 이 값은 runner 연결 인증용이며 새 사업자 API 키가 아니다. 같은 값을 n8n의 기존 운영 자격증명 저장소에서 Header Auth로 관리한다. 비밀값을 화면에 출력하거나 shell 명령 인수·히스토리·Git에 기록하지 않는다.

```sh
python -m integrations.n8n.cross_review.server --db n8n-private/cross-review.sqlite3 --mode mock --port 8791
```

기본 주소는 `127.0.0.1:8791`이다. `n8n-private/`는 Git 제외 경로이며 DB와 보호된 운영 설정을 보관한다. mock 서버의 `/dispatch`·`/start`·`/complete`·`/fail`은 `MOCK_TRANSPORT_DISABLED`로 차단한다. mock 서버를 켜도 실제 사업자 요청을 n8n에 넘길 수 없다. 모의 종단 시험은 테스트가 Engine을 직접 호출한다.

실제 계정과 무료 크레딧 확인 후 사용할 live 명령은 다음과 같다. 현재는 필요한 운영 증거가 없어 실행하지 않는다.

```sh
python -m integrations.n8n.cross_review.server --db n8n-private/cross-review.sqlite3 --mode live --port 8791 --installation n8n-private/installation.json --credit-proofs n8n-private/credit-proofs.json
```

운영 설정에는 비밀값 대신 검증된 참조와 비용 근거만 넣는다. 실제 잔액을 대신하는 예시 credit proof를 만들어 호출 게이트를 해제하지 않는다.

| 파일 | 검증할 필드와 의미 |
|---|---|
| `installation.json` | 설치 확인 `verified`, 실제 `n8n_version`, 사업자별 `bindings`의 `credential_ref`·`account_ref`, `model_bounds[model_id]`의 `verified`·`price_as_of`·`currency`·`maximum_request_cost`·`max_output_tokens`·`max_input_bytes`·`input_per_million`·`output_per_million` 및 필요 시 `cached_input_per_million`·`cache_creation_per_million`·`allowed_actual_models`. 입력·출력 상한·단가·허용 실제 모델과 요청 최대비용의 실제 근거가 필요 |
| `credit-proofs.json` | 계정별 배열: `account_ref`, `provider`, `currency`, `available`, `proof_id`, `verified_at`, `expires_at`, `paid_fallback:false`. 시각은 epoch 초. 무료 크레딧의 확인 시각·유효기간과 24시간 신선도 검사 적용 |

같은 proof ID를 다시 넣어도 이미 사용한 크레딧이 새로 충전되지 않는다. 진행 중·접수 불명 호출의 예약을 새 설정으로 없애지 않는다. 모델별 예약은 검증된 최대 요청비용보다 작을 수 없다. job의 통화·단가·실제 모델 허용 목록은 보호된 설치 설정과 정확히 대조하며 job에 임의의 0원 단가를 넣어 비용을 축소할 수 없다. 현재 설치 버전의 n8n에서 검증되지 않은 옵션을 운영에 활성화하지 않는다.

모든 HTTP 경로는 `X-LK-Runner-Token` header 인증과 정확한 loopback Host를 요구한다. 브라우저 Origin이 있는 요청은 거부한다. URL query에 토큰을 넣지 않는다.

| 경로 | 기능 |
|---|---|
| `GET /health` | 모드·비용 정책·runner 사업자 네트워크 없음·BSO 자동 동기화 없음 확인 |
| `GET /jobs/{job_id}` | 사건 검토 요약과 상태 조회 |
| `POST /jobs` | 계약 검증 후 접수; 입력 body는 검토 job |
| `POST /dispatch`, `/start`, `/complete`, `/fail` | live n8n 전용 예약·시작 fence·응답 수집·불명확 실패 기록 |
| `POST /watchdog` | 영속 원장의 만료 실행권·중단 상태 점검 |
| `POST /resume` | 기존 job의 재개 게이트 검사; 접수 불명 호출의 강제 재실행 기능 아님 |
| `POST /bso-export` | 기존 수동 import용 패키지 반환; BSO 자동 쓰기·읽기 확인 아님 |

### n8n 연결

기본 생성 명령은 비밀값과 실제 계정 참조가 없는 템플릿 4개를 만든다.

```sh
node scripts/build_n8n_cross_review.js
```

출력은 `integrations/n8n/cross-review-{dispatcher,reviewer,watchdog,error-handler}.json`이다. 모두 `active:false`, 설치 확인 전 상태이며 기본 미설정 계정은 실행을 차단한다. 실제 설치용 참조는 Git 제외 경로에서 따로 생성한다.

```sh
node scripts/build_n8n_cross_review.js n8n-private/cross-review n8n-private/cross-review-bindings.json
```

binding 파일은 정확히 `runner`·`anthropic`·`google`·`openai` 네 키를 사용한다. 각 값은 기존 `httpHeaderAuth` 이름인 `credential_ref`와 `account_ref`이며 runner의 계정 참조는 생략할 수 있다. Cloud 연결에는 `runner.base_url`로 실제 승인된 HTTPS 원장 주소를 지정한다. 생략한 기본값은 self-hosted용 `http://127.0.0.1:8791`이다. 외부 주소에 인증값·query·fragment·사설/IP 호스트를 넣지 않는다. 실제 인증값을 설정 JSON에 넣지 않는다. private 출력은 `n8n-private/` 아래만 허용하며 symlink를 거부하고 파일 권한을 제한한다. `/start` 전후에 계정·자격증명 참조를 다시 대조하므로, 노드에서 선택한 실제 자격증명과 runner 설정의 참조가 정확히 일치해야 한다.

n8n Cloud에서는 현재 Python/SQLite 서버를 Code 노드나 Execute Command로 실행할 수 있다고 가정하지 않는다. 이미 비용 없이 이용할 수 있음이 확인된 상시 호스트·영속 디스크와 인증된 HTTPS reverse proxy를 먼저 확보해야 한다. 원장 서버는 loopback 바인딩을 유지하며 프록시는 upstream `Host`를 정확히 `127.0.0.1:8791`로 설정하고 `X-LK-Runner-Token`을 전달한다. `base_url`에 경로 접두사가 있으면 프록시에서 이를 제거해 `/dispatch`·`/start` 등의 원래 경로로 전달한다. 실제 DNS·TLS·접근 경로는 활성화 전에 별도 확인한다. 원문·인증 헤더의 프록시 로그 저장을 차단한다. 모든 원장 HTTP 노드는 redirect를 따르지 않는다. 세션용 작업 환경을 영구 운영 호스트로 간주하거나, 새 유료 호스팅·터널·도메인을 자동 개설하지 않는다.

- 생성된 JSON은 모두 비활성 상태로 검토한다. 빈 워크플로에 가져오고, 기존 접수·라우터의 원본 JSON을 덮어쓰지 않는다.
- 실제 설치 버전에서 노드 버전·자식 워크플로 호출·대기 옵션을 확인한다. 두 분기가 그려져 있다는 이유로 동시 실행을 선언하지 않는다.
- reviewer 자식 워크플로를 먼저 가져오고 dispatcher의 호출 대상에 실제 자식 워크플로 ID를 연결한다. 별도 오류 처리와 watchdog의 연결·활성 상태도 실제 설치에서 확인한다.
- Claude·Gemini·GPT HTTP 노드에는 **기존 n8n 자격증명**을 편집기에서 연결한다. 키를 Code 노드·JSON 본문·Git·보고서에 붙여넣지 않는다.
- runner는 기본적으로 loopback에만 바인딩하고, n8n 요청에는 별도 header 인증을 연결한다. 인증값은 환경변수 또는 자격증명 저장소에서 전달한다. 공유 header를 명령줄·URL query·로그에 넣지 않는다.
- n8n이 컨테이너 안에 있으면 `127.0.0.1`은 해당 컨테이너를 뜻한다. 실행 배치와 접근 경로를 먼저 검증한다. 편의를 위해 runner를 외부 인터페이스에 무인증 공개하지 않는다.
- HTTP 대상 사업자와 경로는 운영 설정으로 제한한다. 문서 안 URL·지시문으로 대상 주소를 바꾸거나 shell·메신저·파일 전송을 실행하지 않는다.
- 모델 원문 입력·응답이 n8n 성공·실패·수동 실행 기록에 중복 저장되지 않도록 저장·정리 정책을 확인한다. 디버그 실행 역시 사건자료를 저장할 수 있으므로 합성자료로만 시험한다.

### 모의시험과 활성화

외부 호출이 없는 합성 시험을 먼저 실행한다. 모의 응답의 provider·model·request ID는 실제 사업자 실행 증거가 아니다. 정상·불일치·한 검토자 실패·버전 충돌·예산 부족·중단 복구를 시험하고 결과를 [STATUS.md](STATUS.md)의 각 항목에 연결한다.

```sh
python -m unittest discover -s tests/cross_review -v
python -u scripts/run_cross_review_mock.py NEW_DIR
node scripts/build_n8n_cross_review.js
node tests/validate_static_site.js
git diff --check
```

`NEW_DIR`는 아직 없는 디렉터리다. [재현 스크립트](../../scripts/run_cross_review_mock.py)는 기존 파일을 덮어쓰지 않고 정상 3단계·불일치 수정/재검증 7단계의 합성 증거와 수동 BSO 패키지를 만든다. 저장소의 [정상 증거](evidence/normal-mock-evidence.json)와 [수정·재검증 증거](evidence/discrepancy-mock-evidence.json)는 실제 사업자 호출·BSO 자동 반영·크레딧 확인 증거가 아니다. 최종 시험 개수와 실행 로그는 [STATUS.md](STATUS.md)에 있다.

실제 호출 활성화는 무료 크레딧·계정·모델·자료 전송 범위가 확인된 경우에만 가능하다. 먼저 공개 또는 합성자료로 정상 사례와 수정·재검증 사례를 실행한다. 비공개 사건자료는 기존 공개 접수 경로에 넣지 않는다. 별도 승인된 사건자료 경로와 접근·보존 정책이 준비되기 전에는 실행하지 않는다.

n8n Gateway·Assistant 크레딧과 각 사업자의 직접 API 크레딧은 별도 잔액이다. 현재 native HTTP 어댑터가 Gateway 잔액을 사용한다고 표시하지 않는다. 로그인 후 실제 버전·플랜·지원 모델·무료 잔액·만료와 유료 자동 충전 설정을 확인한다. Gateway를 사용하려면 해당 경로와 실행 영수증을 검증하는 별도 어댑터가 필요하다.

## 4. 작업 접수와 비용

기존 `lk-bso-job/1.0` 어댑터는 PUBLIC·SYNTHETIC 제한을 유지한다. 신규 검토 계약은 job·사건·자료 등급·승인 범위·예산·원본 목록·snapshot·manifest·산출물·프롬프트·모델 설정을 결합한다. 누락·충돌은 공급자 호출 전에 차단한다.

현재 결정론적 업무 게이트는 `OWNER_COMPARISON`과 제한된 `FORMATTING`·`FORMAT_REVIEW`다. 다른 업무는 P1 `TASK_SCOPE_UNSUPPORTED`로 보류한다. 원·천원, 명시적 합계/곱셈, 최종 HALF_UP/DOWN 외에 ㎡·평·지분·중간 반올림은 전용 규칙이 필요하다. 일반 법률·의견서 전체 검증이나 서술형 초안의 소유자별 수치 추출이 구현된 것으로 표시하지 않는다.

원본은 SHA-256·페이지 수·OCR/추출 버전·이미지 범위와 함께 고정한다. 로컬 경로나 접근 불가 링크만 AI에 전달한 작업은 원본 검토로 표시하지 않는다. 현재 사업자 어댑터는 전체 추출 텍스트 페이지를 제공하며 `EXTRACTED_TEXT_ONLY`로 표시한다. 원본 PDF 이미지·도면을 전송하거나 판독하는 어댑터는 포함하지 않는다. 긴 자료의 자동 분할·수집 계획도 현재 미구현이므로 입력 상한을 넘으면 호출 전 보류한다. 이미지·표 검토 범위를 제한해 표시하고 토큰 제한에서 조용히 잘라내지 않는다.

예산은 통화와 단가 기준일을 갖춘 정확한 십진수로 계산한다. 병렬 호출 전 필요한 예약을 원자적으로 확보한다. job 금액 상한과 확인된 무료 크레딧 상한 중 더 낮은 한도를 적용한다. 무료 크레딧 정책은 잔액 증거 없이 0원 호출을 허용한다는 뜻이 아니다.

중요 작업의 설계 기본 호출 계획은 최초 검토 3회, 자동 수정 1회 포함 시 총 7회이며 실패를 포함한 시도 상한은 10회다. 분할·별도 초안 작성은 시작 전에 계획과 예약에 포함한다. 금액 상한이 호출 수보다 우선한다. 자동 수정은 기본 1회이며 원본은 수정하지 않는다.

잔액·가격·사용량을 모르면 비용을 `0`으로 기록하지 않는다. 미확정 비용과 예약을 남기고 추가 실행을 차단한다. 어댑터의 사용량×설정 단가 계산은 최종 청구서 확인과 구분한다. 사용량이나 캐시 단가가 없으면 비용은 미확정이며 예약을 유지한다. 무료 크레딧 소진·만료·모델 미지원 시 유료 fallback 없이 중단한다. 예산·승인 범위를 바꾸어 기존 ID의 입력을 덮어쓰지 않는다. 변경 계약에 맞는 새 요청을 발급하고 기존 호출·비용 이력은 보존한다.

## 5. 정상 결과와 BSO 반영

Claude와 Gemini는 동일 snapshot·초안을 서로의 답변 없이 검토한다. 필수 검토·범위·runner 영수증·규칙 검사가 완료된 뒤 GPT가 원본 근거별로 채택·기각·미해결을 제시한다. 다수결·모델 확신 점수·모델의 실행 주장으로 통과시키지 않는다.

수정본은 새 산출물 버전·해시로 두 검토와 판정을 다시 수행한다. 이전 승인이나 지연 응답을 새 버전에 적용하지 않는다. P0·P1 또는 중요한 검토 누락이 남으면 최종 사용 가능으로 표시하지 않는다.

현재 BSO의 결과 회수는 [기존 수동 JSON 가져오기](../LK_BSO_RESULT_RETURN.md)다. 신규 원장의 반영 시험이나 파일 패키지 생성만으로 실제 BSO 자동 쓰기·읽기 확인 완료를 선언하지 않는다. 실제 자동 반영 성공에는 job·snapshot·산출물 버전/해시·검증/승인 상태·반영 문서 ID를 다시 읽어 일치시킨 영수증이 필요하다. 읽기 실패·불일치 또는 수동 회수는 `PARTIAL`이다.

`READY_FOR_HUMAN`은 정확한 버전의 사람 검토 대기다. 사람의 명시 승인·실제 적용·외부 제출은 별도 상태와 증거를 요구한다. 모델 응답이나 결과 import가 승인·적용·제출 상태를 부여하지 않는다. 외부 발송·메신저 알림은 연결하지 않는다.

## 6. 중지·재개·오류 조사

중지할 때 새 작업 디스패치를 먼저 비활성화한다. 진행 중인 호출과 예약을 기록하고 runner를 정상 종료한다. 프로세스를 껐다고 이미 접수된 사업자 호출이 취소되거나 비용이 사라진 것으로 처리하지 않는다.

재개할 때 새 원장을 만들지 말고 기존 영속 원장을 연다. 적용 코드·설정·원본·산출물 해시를 대조한 뒤 미완료 작업, lease 만료, 진행 중 호출과 비용 예약을 확인한다. 별도 감시 흐름에서 장기 대기·실행권 만료·호스트 오프라인을 탐지하며, 오류 워크플로만으로 복구를 가정하지 않는다.

| 상황 | 처리 |
|---|---|
| 동일 job·동일 입력 | 기존 결과와 상태 반환, 새 호출 금지 |
| 동일 job·다른 입력 | 충돌 차단, 새 job 요구 |
| 한 검토자 실패 | 부분 결과 보존, 성공 종료·QUICK 자동 전환 금지 |
| 인증 오류 | 재시도하지 않고 자격증명 상태 확인 |
| 429·일시 오류 | 사업자 조건·접수 여부·남은 예산 확인 후 안전한 경우 최대 1회 |
| 접수 불명 timeout | `BLOCKED_RECONCILE`, 무조건 재호출 금지 |
| 호출 중 lease 만료·재시작 | 이전 호출 ID·사업자 기록·예약을 대조, 만료만으로 재디스패치 금지 |
| 이전 버전 지연 응답 | 감사 이력 보존, 현재 판정에 합치지 않음 |
| 무료 크레딧 미확인·소진 | 추가 호출 차단, 유료 fallback 금지 |
| BSO read-back 불일치 | 반영 성공 금지, 이전 기록과 차이 조사 |

오류 조사에는 job·snapshot·산출물 버전/해시·시도·n8n 실행 ID·runner 상태·요청 ID·실제 모델·시각·응답 해시·예약 및 정산 상태를 사용한다. 사건 원문, API 키, 인증 헤더와 전체 제공자 오류 객체를 일반 로그에 출력하지 않는다. 요청 접수 여부가 불명확하면 사업자 기록과 대조할 때까지 정확히 한 번 과금을 보장한다고 설명하지 않는다.

미확정 비용의 조정에는 관리자용 Python API `Ledger.reconcile_cost(ticket_id, actual_cost, proof, now)`가 있다. HTTP/CLI·모델 callback에는 노출하지 않는다. 관리자가 실제 사업자 기록을 확인한 뒤 `source:PROVIDER_RECORD`, `provider`, `account_ref`, `request_id`, `reference`, `verified_at`만 갖는 proof를 제공한다. `reference`는 해당 사업자 공식 HTTPS 주소이며 인증정보·query·fragment를 포함하지 않는다. 계정·요청 ID·시각을 기존 호출과 대조하고 원래 영수증을 보존한다. 확인된 0원도 같은 증거가 필요하다. 이 함수가 사업자 기록의 진위를 직접 조회하는 것은 아니며, 정산은 재개·재호출·검토 성공·사람 승인을 부여하지 않는다.

## 7. 자격증명 교체와 접근·보존

자격증명 교체는 새 디스패치를 중지하고 진행 중 호출을 식별한 뒤 n8n 또는 관리형 비밀 저장소에서 수행한다. 기존 자격증명 참조를 새 값에 연결하고 승인된 무료 크레딧·계정 범위를 다시 확인한다. 새 키를 채팅·코드·설정 예시에 기록하지 않는다. 자격증명 교체를 실패한 호출의 자동 재시도 근거로 사용하지 않는다.

원본·snapshot·응답·영수증·원장은 사건 정책으로 접근을 제한한다. 비공개 원문과 응답을 Git·공유 폴더·일반 실행 로그에 보관하지 않는다. 작업 디렉터리·DB·백업의 OS 권한과 백업 암호화를 검증한다. 실제 자료별 보존 기간이 미정이면 임의 기간이나 자동 삭제를 적용하지 않는다. 원본과 호출·비용·승인 이력은 보존하고, 임시 복제본만 승인된 만료 정책에 따라 정리한다.

## 8. 롤백

1. 신규 디스패치를 중지하고 실행 중 요청·원장·예약·미확정 비용을 기록한다.
2. 변경 전 백업의 워크플로·코드·설정 버전으로 되돌린다. 신규 교차검증 흐름은 비활성 상태로 둔다.
3. 원본·산출물·기존 판정·승인·실행 영수증·실제 호출·비용 기록을 삭제하거나 이전 DB로 덮어써 없애지 않는다.
4. 되돌린 버전과 현재 원장 계약이 호환되는지 확인한다. 호환되지 않으면 재실행을 막고 읽기 전용 보존·별도 복구 계획을 사용한다.
5. 기존 BSO 접수·중복 방지·수동 결과 가져오기와 보류 게이트를 합성자료로 확인한다.
6. 복구한 커밋·워크플로 버전·실제 시험 결과·남은 미확정 호출을 상태표에 남긴다. 원장 초기화나 재접수로 비용 이력을 숨기지 않는다.
