# 보상전략 OS v0.1 산출물 정리

## 기능정의서

입력은 토지보상 감정평가서 PDF이며, 출력은 비교표준지·대상토지 개별요인·비교사례·그 밖의 요인·평가명세의 canonical JSON, 법인별 비교표, 검토 큐, 시용 준비도 보고서다. 자동 결과는 검토 후보로만 취급한다.

## 화면설계서

v0.1 사용자 흐름은 다음 5단계로 제한한다.

1. 평가서 선택
2. 분석 진행상태 확인
3. 법인별 핵심 수치 비교
4. 검토 필요 항목 확인
5. JSON·Markdown·ZIP 결과 저장

기존 5단계 반응형 앱셸과 연결하되, 신규 UI 확장은 v0.2 이후로 보류한다.

## 데이터 구조표

| 객체 | 핵심 필드 |
|---|---|
| source | 파일명, 페이지 수, 텍스트층 페이지, OCR 페이지 |
| page_roles | 페이지, 역할, confidence, 판정근거 |
| standard_selection | 표준지 지번, 기준연도, 공시지가, 근거 |
| subject_to_standard_factors | 대상지번, 6개 조건, 종합치, 이유문구 |
| case_selection | 사례유형, 소재지, 지번, 현황, 가격시점, 단가 |
| standard_to_case_factors | 표준지↔사례 조건별 비교 및 종합치 |
| other_factor | 사례 산정행, 표준지 산정행, 격차율, 결정값 |
| land_schedule | 일련번호, 동, 지번, 면적, 지분, 단가, 평가액 |
| verification | 산식 검증과 허용오차 결과 |
| comparison_set | standard·subject·case, gis_ready, blocking_fields |
| review_queue | 우선순위, 경로, 검토 사유 |

각 추출값은 value, status, evidence를 가진다. status는 EXTRACTED, REVIEW_REQUIRED, NOT_FOUND, NOT_APPLICABLE, OCR_FAILED로 제한한다.

## 포트폴리오 설명문

토지보상 실무 9년의 평가서 해석 경험을 바탕으로, 감정평가서 PDF에서 비교표준지·개별요인·비교사례·그 밖의 요인·평가명세를 구조화하고 법인별 차이와 수동검토 대상을 제시하는 로컬 AI 보상분석 MVP를 설계했다. 광명시흥과 익명시 샘플·예시지구의 서로 다른 평가서 구조를 회귀검증 자료로 사용했으며, 불확실한 값은 자동 확정하지 않고 근거 페이지와 함께 검토 큐로 넘기는 안전한 실무 보조 구조를 구현했다.
